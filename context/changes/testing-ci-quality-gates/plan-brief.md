# CI Quality Gates — Plan Brief

> Full plan: `context/changes/testing-ci-quality-gates/plan.md`
> Research: `context/changes/testing-ci-quality-gates/research.md`

## What & Why

Wire vitest and `astro check` into GitHub Actions so the existing test suite
and TypeScript types block PR merge on failure. The 96-test suite is green and
fully hermetic, but the CI pipeline has never run it — tests exist only on
developers' machines and catch nothing at merge time.

## Starting Point

`.github/workflows/ci.yml` runs `npm ci → astro sync → lint → build`, with no
test or typecheck step. The `deploy` job has `needs: ci`, so a single CI job
gates both PR merges and Cloudflare deploys. The test suite (`npm run test`,
vitest 4, `vitest.config.ts`) and typecheck command (`astro check`, already
installed) both exist; they have simply never been wired into CI. One coverage
gap remains: `campaigns/index.ts` (GET list + POST create) has no test file.

## Desired End State

Every PR to `main` triggers typecheck and vitest in the `ci` job before the
build. A single test failure or TypeScript error blocks both the merge and the
deploy (via `needs: ci`). GitHub branch protection marks `ci` as a required
status check. `campaigns/index.ts` validation logic is regression-guarded.
`test-plan.md` §5 accurately describes the actual gate state.

## Scope

**In scope:**
- New integration test file for `campaigns/index.ts` (GET + POST)
- `"typecheck": "astro check"` script in `package.json`
- Two new steps in `ci.yml`: `npm run typecheck`, `npm run test`
- Branch-protection rule via `gh api` (required `ci` check on `main`)
- `test-plan.md` §5 correction and §7 / §8 updates

**Out of scope:**
- `auth/signout.ts` tests
- Coverage reporting in CI
- Pre-push git hook
- E2E tests
- Cloudflare deploy workflow changes

## Architecture / Approach

The test step needs no secrets because `tests/setup.ts` mocks `astro:env/server`
at the module level. `astro check` needs no secrets because it type-checks
against stubs generated by `astro sync`, which already runs as an earlier CI
step. Both steps are inserted after `npm run lint` and before `npm run build`
(fail-fast ordering). Branch protection is a GitHub repo-settings concern
separate from the workflow file — the `gh api` command in Phase 3 is what
makes the check block merges, not the YAML step alone.

## Phases at a Glance

| Phase | What it delivers | Key risk |
|---|---|---|
| 1. campaigns/index test | Regression-guards GET list + POST create before the gate locks in | `getUserCampaigns` helper mock must resolve to the campaigns table correctly |
| 2. Wire CI gates | `ci.yml` runs typecheck + tests on every PR; both steps hermetic | `astro check` may surface pre-existing type errors; run locally first |
| 3. Branch protection + docs | `ci` check required to merge; test-plan.md §5/§7/§8 corrected | `gh api` requires admin token scope — verify before running |

**Prerequisites:** Phase 1 test must pass locally before Phase 2 commits to `ci.yml`; Phase 2 must be merged and the CI job named `ci` confirmed before Phase 3 sets branch protection.
**Estimated effort:** ~1 session across 3 phases; Phases 1 and 2 are the implementation work; Phase 3 is config + docs (~30 min each).

## Open Risks & Assumptions

- `astro check` may surface pre-existing TypeScript errors not caught by `astro build`. Run `npm run typecheck` locally as a pre-flight before committing Phase 2.
- Branch-protection `gh api` requires admin scope on the repo token. If the local `gh` session lacks it, fall back to the GitHub UI (Settings → Branches → Protection rules → add `ci` as required check).
- `strict: false` in branch protection means branches don't need to be up to date with `main` before merging — acceptable for now; tighten to `strict: true` when merge-train style is adopted.

## Success Criteria (Summary)

- `npm run test` passes with 13 test files after Phase 1
- A PR with a deliberately failing test cannot be merged via the GitHub UI after Phase 3
- `test-plan.md` §5 no longer claims typecheck was already wired
